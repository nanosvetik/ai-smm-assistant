# Состояние фронтенда

Что реализовано и проверено живыми вызовами через настоящий браузер (React+Vite dev-сервер + прокси на бэкенд). Дизайн-ориентир — `design-brief-ателье.md` (Бриф 1 — лендинг, Бриф 2 — кабинет/онбординг). Грабли — `docs/gotchas.md`, история решений — `docs/decision-log.md`.

**Статус:** лендинг, онбординг, кабинет эксперта и страница результатов готовы.

## Стек и оформление

- React 18 + React Router 6 + Vite 5 + TypeScript ~5.6 (та же версия, что в `backend`). **Не** дефолты `npm create vite@latest` — они ставят несовместимый стек, см. `docs/gotchas.md`.
- Без state-менеджера и CSS-фреймворка — `useState` и обычный CSS на компонент, оправдано объёмом.
- `gsap`/`@gsap/react` — только для лендинга, в кабинете/онбординге/результатах не используются.
- `react-markdown` + `remark-gfm` (без плагина не рисуются GFM-таблицы), `js-yaml`, `exceljs` (динамическим импортом), `react-markdown`-документы всегда без frontmatter (`lib/markdown.ts`, `stripFrontmatter`).
- **Дизайн-токены** (`src/index.css`) — палитра из брифа: слива `#4A2545` только акцент, изумруд `#1F5C42` только «готово», не конкурируют за одно значение. Плейсхолдеры полей стилизованы явно (`color: var(--color-muted); opacity: 1` — `opacity` перебивает дополнительное затемнение в Firefox). Сверх палитры брифа один токен — `--color-muted-strong: #6b7064`: `--color-muted` (#a3a89c) даёт к фону контраст ~2.1:1 при норме 4.5:1, и набранный им нажимаемый текст (`btn-quiet`) читался как выключенный; это тот же серо-оливковый, но темнее, только для второстепенных действий.
- **Документы агентов** (`.stage-document`, `.results-packaging-body`, `.results-script-body`) получают кегли и отступы заголовков в `index.css`: markdown наследовал глобальный `margin: 0` и браузерные размеры, из-за чего заголовок документа выходил ровно как заголовок экрана (28px), а воздуха над заголовками не было вовсе. Ступени 22/19/16, ширина строки 70ch.
- **`AppHeader.tsx`** — тихая шапка с брендом в онбординге и кабинете (`lib/brand.ts`, `BRAND_NAME`; лендинг берёт название оттуда же). До этого рабочие экраны открывались сразу с формы или сайдбара, и пришедший по ссылке из почты не видел, куда попал.
- **Типографика:** Alegreya (заголовки, editorial-serif) + Golos Text (текст/интерфейс) — **не** Fraunces/Figtree из брифа: у них нет кириллицы. Обе самохостятся как `.woff2` в `src/assets/fonts/`, не через CDN — тот же self-hosted принцип, что у остальной инфраструктуры.
- **Vite dev-прокси** (`vite.config.ts`): `/api`, `/media`, `/uploads` → `http://localhost:3000`. Тот же same-origin паттерн, что будет в проде через nginx/Caddy — cookie сессии работает без CORS-настройки. **Любой новый статический путь на бэкенде требует нового блока здесь.**
- **Адаптивность:** брейкпоинты `@media (max-width: 760px)` (кабинет — колонкой, сайдбар на всю ширину) и `@media (max-width: 420px)` (тоггл B2C/B2B в столбик).

## Экраны

### `LandingScreen` (`/`)

Публичный лендинг с формой заявки. Продаёт **продукт целиком, амбициозно** — не демо и не MVP; демо только способ дать потрогать упрощённую, но настоящую систему.

- **Фотографии** (`src/assets/images/`) — три изображения, сгенерированные самим сервисом (`seedream-4.5`) под наши персоны: мыло ручной работы (hero), уголок кабинета косметолога (секция контраста), керамика (секция «5 вещей»). Исходники 2048px ужаты до 1000px, 80–120 КБ. Банк картинок от тестовых прогонов не подошёл: персона-психолог даёт сумеречные интерьеры про одиночество, персона аниме-магазина — пастель с чужими товарными знаками, плюс два кадра с браком генерации (фигура без головы, имитация стокового вотермарка). Импорт `.jpg` требует `src/vite-env.d.ts` — без него дев-сервер работает, а `tsc` падает.
- Карточка примера в hero собрана **как настоящий пост**: картинка сверху, текст под ней, подпись «Текст и картинка сделаны сервисом» — доказательство, что визуал сервис тоже делает сам. Колонки hero выровнены по центру (`align-items: center`): карточка с фото вдвое выше текстовой, при выравнивании по верху под кнопкой оставалась дыра.
- **Раскладка содержательных секций** — `.landing-split`: заголовок с короткой курсивной подводкой слева, содержание справа. Секции «То, за что обычно платят маркетологу», «Это только начало» и секция заявки иначе выстраивались одной узкой колонкой у левого края с пустой правой половиной. Мобильный медиазапрос `.landing-split` (≤880px) стоит в CSS **выше** правила ширины колонок у `.landing-cta` — поэтому последнее ограничено `@media (min-width: 881px)`, иначе при равной специфичности оно перебивало бы схлопывание.
- GSAP по минимуму: одна оркестрованная последовательность появления hero при загрузке (`useGSAP`, стаггер) и мягкое проявление секций на скролле — на `IntersectionObserver`, **не** `ScrollTrigger` (тот прятал секции сразу и показывал только после собственного пересчёта позиций; при сбое пересчёта форма заявки оставалась невидимой — см. `docs/gotchas.md`). `gsap.matchMedia` уважает `prefers-reduced-motion`.
- Раздел **«То, за что обычно платят маркетологу»** — 5 шагов ценности по реальному порядку пайплайна (портрет ЦА → распаковка экспертности → разбор стиля/ниши → упаковка профиля → готовый контент), каждый явно называет, почему это дорого сделать самому. Позиционирование ЦА — основная ценность продукта, не только готовый текст.
- Раздел **«Это только начало»** — глимпс полной SaaS-версии (больше площадок, вертикальные видео из сырого материала, сценарии сторис, воронки в контент-плане), ни разу не упоминая «демо».
- Контраст-блок «не шаблон, который выдаст любой чат-бот» — общий ИИ-текст vs реальный голос — вынесен в **сплошную сливовую полосу на всю ширину окна** (`.landing-contrast-band`, содержимое остаётся в колонке 1160px). Единственный тёмный акцент страницы: после него светлые секции читаются как воздух, а не как незаполненное место. Живой пример — светлая карточка с фотографией, ботовская реплика — блёклый контур без фона, отцентрованный по вертикали (`align-self: center`), иначе слева оставалась дыра во всю высоту карточки.
- **Фактура фона** — тонкое зерно (`--landing-grain`, SVG `feTurbulence` в data-URI, без внешних запросов) фоном самой страницы и продублировано на сливовой полосе. Именно фоном, не оверлеем поверх контента: поверх шум замыливал текст.
- **Единственное место, где звучит «демо»** — блок `.landing-demo-note` у формы заявки (плум-заливка, левая рамка): оговорка про упрощённость («короткая анкета вместо полного интервью даёт более общий, но честный разбор»), затем **список состава** и строка про площадки. Состав сверен с кодом, а не с намерением: пост с картинкой — на каждую площадку (`copywriter` версионирует площадки независимо), для ВК — 2–3 идеи рилсов (столько просит `prompts/content-planner.md`, ровно три не гарантированы), один сценарий и одно видео. **Это единственное место на лендинге, где названы Telegram и ВК как текущий объём** — в роадмапе они звучат как обещание на будущее, из него текущие площадки не вычитываются.
- Форма — `{ email, name? }` через `submitAccessRequest`. `BRAND_NAME = "Своими словами"` вынесен в одну константу.

### `TokenExchangeScreen` (`/onboarding/:token`)

Вызывает `GET /api/access/:token` при монтировании, различает `link_already_used`/`link_expired`/`link_not_found` по коду ошибки и показывает разный текст на каждый случай в стиле дизайн-системы (не сырой JSON). При успехе редиректит на `/onboarding`.

### `OnboardingScreen` (`/onboarding`)

Форма по Брифу 2:
- Короткие поля сверху: тоггл B2C/B2B (с пояснением), свои соцсети 0–2, конкуренты 2–3 обязательных (`LinksField.tsx`, переиспользуется для обоих списков). `ownLinks` стартует **с одной пустой строкой** — при старте с пустого массива раздел визуально выглядел свёрнутым рядом с предзаполненными полями конкурентов, и эксперт вписывал свои ссылки в конкурентов. Поле остаётся необязательным, пустая строка отфильтровывается при сабмите.
- Ниже — **карточка-интервью** (`InterviewCard.tsx`, сигнатурный элемент): 5 открытых вопросов поданы как диалог с аватаром-меткой «„» (открывающая кавычка читается по-русски как «здесь идёт речь»), не стена textarea.
- Пятый вопрос — путь эксперта: *«Как вы начали своё дело? Учились специально, набили руку на практике, или увлечение просто переросло во что-то большее — не важно, какой из вариантов ваш.»* Формулировка проверена не только на дипломированном психологе, но и на кейсе «девушка с мылом на кухне».
- Drag-and-drop референсов на этом экране **нет** — переехал на страницу «Рилсы» в кабинете.
- Кнопка «Запустить анализ» намеренно не входит в экран — сабмит только сохраняет анкету и ссылки.
- Курсивные сливовые эйбраузы-`<h2>` над каждым блоком. Строка-«план страницы» (`.onboarding-roadmap`) **удалена** — перечисляла ровно те же три заголовка, что стоят следом на странице, и не показывала, где человек сейчас.
- Крупная „ в шапке — `position: absolute` **в левом поле формы**, не позади текста. Это не откат прежнего решения: во flex-потоке рядом с заголовком (`line-height: 0.6`) глиф вылезал из своей строки на абзац ниже, а заголовок сдвигался вправо и терял общую левую ось с текстом. Ранняя попытка ставить её абсолютом *позади* текста наезжала на буквы — здесь кавычка вынесена за левый край колонки, а ниже 820px встаёт отдельной строкой над заголовком (в поле она бы не поместилась).
- **Поля ответов растут по содержимому** (`GrowingTextarea` внутри `InterviewCard.tsx`, `useLayoutEffect` по значению; `resize`/`overflow` выключены). Фиксированные три строки со внутренней прокруткой прятали середину ответа — а это главное содержательное поле продукта.
- **Экран «Данные сохранены»** — рамка ожиданий для тех, кто пришёл потыкать: `.onboarding-success-note` (плум-плашка, левая рамка, `<strong>Это демо-версия.</strong>` жирным как якорь), «Перейти в кабинет» — настоящая кнопка (`btn btn-primary`), а не текстовая ссылка, чтобы пояснение и действие читались двумя шагами. Селектор пришлось писать как `.onboarding-success .onboarding-success-note` — глобальное `.onboarding-success p` перебивало по специфичности.
- При загрузке анкета докладывается дефолтами `EMPTY_QUESTIONNAIRE`, а `expertPath`/`clientPhrases` отдельно коалесятся к `""`: спред одного объекта поверх дефолтов не спасает — ключ с явным `null` перекрывает `""`.

### `DashboardScreen` (`/dashboard`) — Кабинет эксперта

- Сайдбар ровно на **9 пунктов** (`lib/stages.ts`, `STAGES`), не 1-в-1 с 12 агентами: `visual-style-analyzer`/`profile-header-analyzer` — вспомогательные входы без своего пункта, `editor-in-chief` невидим (встроен в `copywriter`/`reels-writer`).
- Пройденные этапы — изумрудная галочка, текущий (первый непройденный по порядку) — **охряная точка** и полужирное начертание, остальные — серый текст. Мягкая сливовая заливка отдана **открытому сейчас пункту**, а не текущему этапу: по брифу слива означает активное состояние навигации и никогда не означает статус, а раньше выбранный пункт подсвечивался нейтральным серым и у клиента с пройденными этапами слива в кабинете не появлялась вообще. Три смысловых блока (разбор → стратегия → готовый контент) отделены увеличенным отступом (`.sidebar-group-break`), без заголовков и рамок групп.
- «Посты»/«Изображения» показывают по площадке клиента отдельным блоком. «Рилсы» — пункт исчезает из сайдбара целиком, если у клиента нет ВК.
- Для площадочных этапов пустой список площадок явно даёт `false` — `[].every(...)` вакуумно возвращает `true` и рисовал галочку «пройдено» на пустом месте.
- У каждого этапа — одна строка простым языком о том, что он делает (`StageConfig.description`), курсивом под `<h1>`, тем же типографическим приёмом, что эйбраузы онбординга. Пустой стейт ведёт к кнопке («Пока не запускали — нажмите «Запустить» ниже»), а не просто констатирует факт.
- Отсутствие предпосылок переводится в русские подписи (`lib/stages.ts`, `describeMissing`), а не показывает голые agent-слаги.
- Смена этапа сбрасывает прокрутку (`handleSelectStage` → `setActiveKey` + `window.scrollTo(0, 0)`) — в SPA автосброса не происходит.
- Пояснение «Черновик — это честность инструмента…» показывается **один раз на экран** (`StatusLine`, проп `showDraftNote`): на площадочных этапах оно печаталось дважды подряд. Статус и версия у площадок разные и остаются у каждой.
- Превью картинки ограничено `max-height: 440px` — квадратная картинка занимала всю ширину колонки (~745px), и кнопки под ней приходилось искать прокруткой.
- **`Sidebar.tsx`:** на десктопе `position: sticky; top: 40px; align-self: flex-start` (без `align-self` sticky не сработает — flex-родитель растянет колонку). На ≤760px — тонкая sticky-полоска с названием текущего этапа, разворачивающаяся по тапу в оверлей (стейт `isExpanded`, видимость через CSS-медиазапрос, не JS `matchMedia`); затемняющий фон — отдельный `<button>`, не `<div onClick>`, ради клавиатуры и скринридера; выбор этапа закрывает оверлей.

### `ResultsScreen` (`/results/:token`)

Read-only витрина готового демо, рассчитанная на пересылку (потенциальные лиды). Вёрстка сознательно ближе к Брифу 1 (лендинг: тепло, editorial-асимметрия — hero сдвинут влево, чередование текст/картинка через `order` по чётности), не к Брифу 2.

- Показывает только готовый контент: посты в карточке того же стиля, что `.stage-document-post` в кабинете (кружок-„, editorial-serif), плюс картинка/видео рядом. Сценарий рилса скрыт за `<details>`/«Показать сценарий», не открыт по умолчанию.
- **Ширины подобраны под длину строки:** витрина 1080px (не 880) и доли колонок 1.35fr/1fr дают тексту поста ~57 знаков в строке — при 880px выходило ~35, и пост читался рваным столбцом. До 560px кружок-„ в карточке скрыт и поля поджаты: он съедал треть ширины и оставлял ~24 знака.
- **Секция рилса — одна колонка** (`.results-reels-body`): рядом с вертикальным видео в двухколоночной раскладке висела одинокая ссылка «Показать сценарий» и ~500px пустоты.
- Раздел **«Упаковка профиля»** (`.results-packaging`) под основной витриной — `bundle.packaging.documentMarkdown` тем же `ReactMarkdown`+`stripFrontmatter`, в собственной карточке обычного документного стиля (не в стиле поста). `packaging` может быть `null` — на практике не должно, но код не полагается на негласную гарантию.
- Аналитики (ЦА, экспертность и т.п.) нет — см. обоснование в `docs/backend-state.md`.
- Не под сессией — отдельный публичный `fetch` по токену (`lib/api.ts`, `getResults`), не переиспользует кабинетный стейт. Ошибки — тот же паттерн сообщений, что в `TokenExchangeScreen`.

## Компоненты

- **`StagePanel.tsx`** — панель этапа. Выбирает рендерер документа через `DocumentBody`:
  - `content-planner` → `ContentPlanGrid` (с честным откатом на `ReactMarkdown`, если json-блок не распарсился);
  - `copywriter` → `PostCard`;
  - `visual-generator` → `ImageGenerationBlock` **вместо** `RunBlock` целиком (единственный этап с полной заменой);
  - остальное → `ReactMarkdown` + `remark-gfm`, frontmatter срезан.
  Под этапом `reels-writer` дополнительно рендерится `VideoGenerationBlock` (не заменяет `RunBlock` — сам сценарий это реальный клиентский контент, скрывать нечего; скрыт только видео-промпт).
- **`RunBlock`** — кнопка запуска рендерится **только пока `!result`**. Как только результат появился, кнопки нет вообще: повторный запуск с фронтенда невозможен. Это демо, платные вызовы под контролем.
- Индикатор ожидания: пока `isRunning` — бегущая полоска (`.stage-progress-bar`, CSS-анимация, не реальный процент — у одного блокирующего запроса прогресса нет) и строка «обычно 1–3 минуты, не закрывайте вкладку». `StageConfig.progressHint` переопределяет текст для `copywriter`/`reels-writer` («2–5 минут» — до 2 генераций + 2 проверок редактора). Пустой стейт на время запуска скрывается.
- **`StatusLine`** — при статусе `черновик-*` показывает пояснение «Черновик — это честность инструмента при неполных данных, не ошибка» (`.stage-status-note`). При `needsManualReview` — предупреждение (`.stage-status-warning`) плюс сам вердикт редактора (`editorFeedback`) в приглушённом блоке `.stage-status-warning-detail`, чтобы клиент видел, что именно не так, а не только факт.
- **`SecondaryBlock`** — второй read-only блок под основным, без кнопки. Через `StageConfig.secondaryAgentSlug`/`secondaryLabel`; пока используется только парой «Анализ аккаунта» + `profile-header-analyzer` (у обоих вход — только own-ссылки, оба независимы от остальных этапов). Бэкенд дёргает `runProfileHeaderAnalyzer` вместе с `runAccountAnalyzer` через `Promise.all`, ошибка второго не роняет ответ.
- **`PostCard`** — карточка поста: мягкий сливовый фон (`--color-plum-soft`), кружок-„ слева (flex, не absolute), текст в editorial-serif крупнее и просторнее. Один яркий акцент на карточку. Аналитические документы остаются нейтральными — эмоциональный акцент нужен только в моменте «вот ваш готовый текст».
  Под карточкой — две `quiet`-кнопки: «Копировать текст» (`navigator.clipboard`, с временной подписью «Скопировано») и «Скачать текст (.txt)» (Blob + `<a download>`). Обе читают `ref.innerText` с уже отрендеренного markdown, не сырой `documentMarkdown` — в буфер уходит то, что клиент видит, без `**`. Ручной правки в интерфейсе нет намеренно: клиент правит текст у себя.
- **`ContentPlanGrid.tsx`** — сетка контент-плана вместо markdown-рендера. Парсит структурированный json (`lib/planData.ts`, `parseContentPlanData` — зеркало backend-парсера, читает колонки `planItems`/`reelsIdeas`/`platforms`). Группирует дни по неделям (`Неделя 1`/`Неделя 2` — чисто по номеру дня 1–14, без календарных дат: их в системе нет, псевдо-даты создали бы иллюзию жёсткого графика), внутри — дни недели, столбцы — только реальные площадки. Дни без постов не выводятся вообще. Отдельным блоком — идеи Reels с хуком и пометкой, нужны ли личные материалы.
  Плашка `.content-plan-download-note` над кнопкой экспорта: «Скачайте таблицу сейчас… больше нигде не сохраняется» — контент-план единственный документ, который не попадает в results-ссылку.
  **«Скачать таблицу (.xlsx)»** — `lib/contentPlanExport.ts`, `exceljs` через `await import()` внутри обработчика (библиотека ~940 КБ, статический импорт раздувал основной бандл почти вдвое). Два листа: «Контент-план» (брендовая сливовая заливка шапки) и «Идеи Reels». **Не `xlsx`/SheetJS** — последняя опубликованная в npm версия несёт две high-severity уязвимости, патчи публикуются только на свой CDN.
- **`ImageGenerationBlock.tsx`** — одна кнопка «Сгенерировать картинку»/«Сгенерировать заново» молча вызывает `POST /agents/visual-generator` (тот же `onRun`, что обновляет `results`) и сразу `POST /agents/generate-image`. Показывает **только готовую иллюстрацию** — без промпта, без модели, без цены: технические детали клиенту не нужны, а два клика были лишней сложностью. Staleness-проверки нет — промпт пишется заново при каждом клике, устаревшей картинки не бывает. Плюс «Скачать картинку» (`<a download>` с человеческим именем `иллюстрация-<platform>.<ext>`).
  **Регенерация тут оставлена** — генерация реально может выйти с браком, и без второй попытки демо-клиент получил бы его как финал.
- **`VideoGenerationBlock.tsx`** — зеркало картиночного (переиспользует его CSS-классы), но **без кнопки регенерации**: $0.84 за вызов, первая генерация окончательная, дальше только «Скачать видео». Вызывает `runAgent("reels-video-generator")` напрямую, не через `onRun` родителя — галочка «пройдено» для «Рилсов» зависит от самого сценария выше.
- **`ReelsReferenceUpload.tsx`** — зона загрузки на странице «Рилсы»: реальные миниатюры (`<img>` по `publicUrl`) с кнопкой «✕» в углу каждой, `deletingId` блокирует повторный клик. Текст явно говорит, что фото участвуют в генерации видео и что при нескольких загруженных в дело идёт **только последнее**.
- **`LinksField.tsx`** — список ссылок с `min`, кнопкой «+ Добавить ссылку» и hint'ом.

## `lib/`

- `api.ts` — типизированная обёртка над `fetch` к `/api/*`. `request()` возвращает `undefined` на `204 No Content` (иначе `res.json()` падает на пустом теле, и `DELETE` в принципе не работал).
- `stages.ts` — конфиг 9 этапов: `key`, `description`, `progressHint`, `secondaryAgentSlug`/`secondaryLabel`, `describeMissing`.
- `markdown.ts` — `stripFrontmatter`. Устойчивый перебор пар `---` (модель кладёт decoy-разделители до настоящего frontmatter), принимает кодфенс с **любым** языком и, если закрывающий ` ``` ` не сразу после frontmatter, ищет его в конце документа; при падении `load()` пробует ещё раз с квотированием значений, содержащих `:`.
- `planData.ts` — `parseContentPlanData`, `groupPostsByDay`, `sortedDays`.
- `contentPlanExport.ts` — генерация `.xlsx` в браузере.
