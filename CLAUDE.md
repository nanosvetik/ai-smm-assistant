Навигационный файл проекта. Здесь только то, что нужно в любой сессии: правила работы, стек, структура, конвенции. **Фактическое состояние кода, история решений и грабли вынесены в отдельные документы `docs/` — читать их по мере необходимости, а не целиком в начале сессии** (см. «Навигация» ниже).

## Что за проект

Веб-сервис для мелкого бизнеса и частных экспертов: анализирует их соцсети и конкурентов, распаковывает целевую аудиторию и экспертность, генерирует контент-план и демо-контент (посты, картинки, сценарий Reels) без «нейрослопа». Учебный/некоммерческий этап, MVP. Бренд — «Своими словами», домен `svoislova-ai.ru`.

Текстовый пайплайн, медиа-генерация, доставка ссылок и витрина результатов реализованы; лендинг, онбординг, кабинет эксперта и страница результатов готовы. Подробности — в документах ниже.

## Git-workflow (обязательно)

**Коммитить каждый завершённый этап работы сразу после его завершения** — не батчить несколько этапов в один коммит. Репозиторий на GitHub (`nanosvetik/ai-smm-assistant`, публичный, `origin`) — коммитим прямо в `master` и сразу пушим, без PR-флоу (соло-разработка). Если подключится ещё один человек — вернуться к этому решению.

Практически: закончили один логический шаг (одна фича, один агент, один эндпоинт, одна правка документа) — сразу `git add` + `git commit` с внятным сообщением + `git push`. Не ждать «дособрать покрупнее».

## Секреты и окружение

`.env` в `.gitignore` — **никогда не коммитить секреты**: `OPENROUTER_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `VK_SERVICE_TOKEN`, `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` и любые будущие ключи.

Опциональные пути: `UPLOAD_DIR`, `BASE_URL` (по умолчанию дев-порт фронтенда `5173` — в проде фронт и API на одном домене через nginx/Caddy).

**Репозиторий публичный.** Кроме ключей, в него не попадает операционная конкретика по серверам: IP-адреса, имена машин, какие порты открыты, как устроен вход. Это не секреты в узком смысле, но вместе они — готовая инструкция для желающих. Такое пишем в `docs/*.local.md` (в `.gitignore`); в отслеживаемых документах — только обезличенные уроки и решения. Тот же принцип касается личных файлов в корне проекта: `omni-claude.bat` игнорируется, потому что содержит токен шлюза.

## Стек

- **Backend:** Node.js + Express, TypeScript (strict).
- **Frontend:** React 18 + React Router 6 + Vite 5 + TypeScript ~5.6, без state-менеджера и CSS-фреймворка.
- **БД:** SQLite через Drizzle ORM (self-hosted одиночный сервер; обоснование и условие пересмотра на Postgres — `docs/decision-log.md`).
- **Пакетный менеджер:** npm, монорепо через npm workspaces (`backend`, `frontend`). `smm-mcp` намеренно вне workspaces — самостоятельный пакет со своим `npm install`.
- **Хранение файлов:** локальный диск + nginx/Caddy как раздача статики, не S3/R2.
- **LLM:** OpenRouter API (OpenAI-совместимый chat completions, слаги с префиксом провайдера — `anthropic/claude-sonnet-5`). Клиент — `backend/src/lib/openrouter.ts`, поддерживает текст и мультимодальные сообщения.
- **Медиа-генерация:** прод-код — `backend/src/lib/imageGeneration.ts` / `videoGeneration.ts` (прямые вызовы OpenRouter). MCP-сервер `smm-mcp` — инструмент разработки, продакшн его не вызывает; подтверждённые слаги моделей там же.
- **Данные клиента:** SQLite по `client_id` — **не** `@modelcontextprotocol/server-memory` (почему — `docs/decision-log.md`).
- **Уведомления оператору:** Telegram-бот, long polling (не webhook — не нужен публичный HTTPS).
- **Почта клиенту:** `nodemailer` поверх произвольного SMTP (`backend/src/lib/email.ts`); при незаданном SMTP флоу не ломается — оператор пересылает ссылку вручную.

## MCP-серверы

Настроены в `.mcp.json` в корне репозитория:
- `smm-visuals` → `./smm-mcp/src/index.js` — генерация картинок/видео.
- `memory` → `@modelcontextprotocol/server-memory` — **память самого Claude Code между сессиями разработки**, не хранилище клиентских данных. `MEMORY_FILE_PATH` указывает на `./data/dev-memory.json` внутри проекта — без этого сервер пишет в общий файл на весь компьютер. Папка `data/` должна существовать заранее, сервер не создаёт её сам (`ENOENT`).

## Конвенции кода

- TypeScript строгий режим (`strict: true`) в обоих пакетах.
- Без комментариев, объясняющих очевидное — только там, где неочевидна причина.
- Не вводить абстракции/фреймворки сверх того, что реально нужно для MVP-объёма.
- Не создавать пустые папки-заготовки под будущий функционал — структура появляется вместе с первым реальным кодом.
- Статус документа агента: числовой порог — это **пол** (принудительно занижает при нехватке данных), а не потолок; качественную самооценку модели не завышать автоматически.
- Не считать, что у клиента обе площадки — Telegram и ВК независимы, Reels существуют только для ВК.

## MVP-объём (не расширять без явного решения)

- Контент-план на 2 недели — только темы/заголовки.
- Полностью генерируются демо-позиции только по реальным площадкам клиента: до 3 (1 пост Telegram, 1 пост ВК, 1 Reels ВК — Reels только если есть ВК), меньше — если площадка одна.
- Доступ — только через ручное подтверждение заявки с лендинга, одноразовая magic-ссылка.
- Дальнейших итераций после демо не планируется: полный контент-план с медиа на 14 дней, масштабирование хранилища, ремаркетинг по tg/vk — вне рамок проекта.

## Открытые вопросы

Все вопросы из раздела 8 спецификации закрыты — см. `docs/decision-log.md`. Единственное незакрытое дело: **живой тест SMTP-отправки** — не проходит из сети пользователя (провайдер блокирует исходящие 587/465), проверяется на реальном сервере; если и там та же ошибка — переходить на HTTP API-провайдера (подробности и обходной путь по DNS — `docs/decision-log.md`, «SMTP-провайдер»).
