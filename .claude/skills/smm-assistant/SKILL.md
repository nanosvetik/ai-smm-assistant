# «Своими словами» — работа с репозиторием

Веб-сервис для мелкого бизнеса и частных экспертов: анализирует соцсети клиента и конкурентов, распаковывает аудиторию и экспертность, собирает контент-план и генерирует демо-контент — пост, картинку, сценарий и видео рилса. Двенадцать LLM-агентов передают результаты друг другу через SQLite, каждый пишет версионированный документ.

Живой сервис: `svoislova-ai.ru`. Этап — учебный MVP, но развёрнутый и работающий.

## С чего начать

1. Прочитать `CLAUDE.md` в корне — навигационный файл: правила работы, стек, конвенции, таблица агентов.
2. Открыть **только тот** документ из `docs/`, который нужен под задачу (таблица навигации там же, в `CLAUDE.md`). Документы большие, читать их целиком в начале сессии не надо.
3. Перед отладкой любого странного поведения — `docs/gotchas.md`. Там записаны грабли, на которые уже наступили: разбор ответов моделей, чужие API, миграции, фаервол.

## Структура репозитория

```
/backend          Express API, TypeScript, SQLite через Drizzle
  src/app.ts        сборка приложения без listen — её же поднимают тесты
  src/index.ts      точка входа: .env, listen, Telegram-бот
  src/agents/       по файлу-оркестрации на агента + pipeline.ts (run-all)
  src/routes/       HTTP-роуты: access, onboarding, agents, results, reelsReferences
  src/parsers/      telegram.ts, vk.ts — посты и шапка профиля
  src/admin/        CLI подтверждения заявок
  src/telegram/     long-polling бот для уведомлений оператору
  src/lib/          токены, OpenRouter-клиент, почта, парсеры документов, медиа, paths.ts
  src/db/           схема Drizzle, подключение, миграции
  drizzle/          SQL-миграции и снапшоты
/frontend         React 18 + Vite: лендинг, онбординг, кабинет, страница результатов
/prompts          системные промпты 12 агентов — самостоятельные документы
/docs             спецификация, состояние бэка и фронта, журнал решений, грабли
/docker           compose-окружение для локального запуска
/deploy           конфиг веб-сервера для боевого развёртывания
/smm-mcp          MCP-сервер медиа-генерации: инструмент разработки, не зависимость прода
/data /uploads /workspace   база, файлы клиентов, сгенерированное медиа — в .gitignore
```

Промпты лежат отдельно от кода намеренно: каждый — документ, который можно прочитать или загрузить в любую нейросеть, не запуская сервис. Код рядом отвечает только за то, чем агента накормить и куда положить результат.

## Запуск

### Быстро, через Docker

```bash
docker compose up --build      # интерфейс на http://localhost:8080
```

Схема базы накатится сама, ключи не обязательны. Порт занят — `WEB_PORT=8090 docker compose up`.

### Без Docker

Нужен Node.js 20 и npm (монорепо на npm workspaces).

```bash
npm install
cp .env.example .env       # заполнить, если нужны живые вызовы моделей
npm run db:migrate         # создаст data/app.sqlite и накатит схему
npm run dev:backend        # API на :3000, с ним Telegram-бот, если задан токен
npm run dev:frontend       # интерфейс на :5173, запросы к API проксируются
```

**Без ключей сервис поднимается.** Лендинг, онбординг и кабинет работают; этапы, которым нужна модель, честно отдают ошибку вместо тихой заглушки. Что отключается при пустом значении — расписано в `.env.example`.

Обязательный ключ для живых прогонов — `OPENROUTER_API_KEY`. Остальное опционально: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_CHAT_ID` (уведомления оператору), `VK_SERVICE_TOKEN` (парсер ВК), `UNISENDER_API_KEY` с почтовыми адресами (письма клиенту), `OUTBOUND_PROXY_URL` (если к моделям нет прямого доступа из вашей страны).

### Пройти путь клиента

Доступ в продукте выдаётся только вручную, кабинет с улицы не открыть. Оставьте заявку на лендинге и одобрите её из командной строки:

```bash
npm run admin:list --workspace backend             # показать заявки
npm run admin:approve --workspace backend -- <id>  # выдать одноразовую ссылку
```

Ссылка напечатается в консоли: по ней открывается анкета, после отправки — кабинет. Ссылка на анкету одноразовая и сгорает, ссылка на страницу результатов — многоразовая и работает без сессии.

## Как вносить изменения

- **TypeScript строгий** в обоих пакетах. Без комментариев, объясняющих очевидное, — только там, где неочевидна причина.
- **Не вводить абстракции сверх нужного для MVP** и не создавать пустых папок-заготовок: структура появляется вместе с первым реальным кодом.
- **Пути к данным — только из `backend/src/lib/paths.ts`**, никогда от `process.cwd()`. Рабочая директория процесса в проде не совпадает с дев-машиной, а ошибка проявляется молча: `better-sqlite3` создаст новую пустую базу вместо того, чтобы упасть. По той же причине точка входа начинается с `import "./lib/loadEnv.js"`, а остальное подключается динамическим `import()` после него.
- **Поменяли схему БД** — `npm run db:generate --workspace backend`, затем `npm run db:migrate --workspace backend`. Тонкости Drizzle (когда генератор требует TTY, как ручная правка журнала молча отключает последующие миграции) — в `docs/gotchas.md`.
- **Правите поведение агента** — правьте `prompts/<агент>.md`, а не код вокруг. Промпт самостоятелен; код только собирает контекст и разбирает ответ. Промпты читаются с диска при каждом вызове, пересборка для их изменения не нужна.
- **Статус документа агента:** числовой порог — это **пол** (принудительно занижает при нехватке данных), а не потолок. Качественную самооценку модели вверх не поднимать.
- **Не считать, что у клиента обе площадки.** Telegram и ВК независимы, Reels существуют только для ВК.
- **Новый код сопровождается тестом**, если трогает разбор документов агентов, прогресс этапов или механику доступа — места, где уже случались живые сбои. Логику, которую надо проверить, выносить в `lib/`: внутри экрана её не протестировать.
- **После работы обновить документ:** бэкенд → `docs/backend-state.md`, фронтенд → `docs/frontend-state.md`, наступили на грабли → `docs/gotchas.md`, приняли или отменили решение → `docs/decision-log.md`. `CLAUDE.md` держать тонким: туда только сквозные правила, не состояние.
- **Коммитить каждый завершённый этап сразу**, не батчить. Репозиторий соло-разработческий: коммит прямо в `master` и сразу push, без PR-флоу.

### Осторожно с платными вызовами

Генерация видео стоит около `$0.56` за клип, картинки — `$0.04`. Кнопки «переделать» у видео нет намеренно. Не запускайте платную генерацию без явного согласия владельца проекта. Текстовые агенты и vision-разбор стоят центы — это другая категория.

## Как проверять ошибки

```bash
npm test                                  # vitest: бэкенд + фронтенд
npm run build                             # tsc + vite, полная проверка типов
npx tsc --noEmit -p frontend/tsconfig.json
```

Тесты покрывают не всё подряд, а места живых сбоев: разбор документов агентов, прогресс этапов, механику доступа, выбор референсов. Сквозной HTTP-тест поднимает приложение на случайном порту с временной базой и проходит путь «заявка → одобрение → открытие ссылки дважды → анкета → ссылка сгорела».

Когда поведение странное:

1. `docs/gotchas.md` — сначала туда. Велика вероятность, что это уже было.
2. Модель вернула документ, который не разобрался, — смотреть `backend/src/lib/frontmatter.ts` и `promptBlock.ts`: там накоплена защита от того, как модели ломают YAML и кодфенсы.
3. Агент «ничего не делает и не падает» — проверить, не пуст ли его вход. Отсутствие данных у большинства агентов штатная ветка, а не ошибка: агент вернёт `undefined`, потребитель отработает без него, и снаружи это выглядит как тишина. Проверять счётчиком строк в таблице, а не чтением кода.
4. Если правили промпт — проверять живым прогоном, а не чтением. Запреты модели обходят по букве, а ужесточённые запреты она распространяет шире, чем задумано; видно это только в выводе.

## Подготовка к публикации

Репозиторий публичный, его читают посторонние.

- **Никогда не коммитить секреты:** `OPENROUTER_API_KEY`, `TELEGRAM_BOT_TOKEN`, `VK_SERVICE_TOKEN`, `UNISENDER_API_KEY` и любые будущие ключи. `.env` в `.gitignore`.
- **Операционная конкретика по серверам** — IP-адреса, имена машин, открытые порты, способ входа — не попадает в репозиторий даже как «не секрет». Такое пишется в `docs/*.local.md`, они игнорируются. В отслеживаемых документах — только обезличенные уроки.
- **Комментарии и документы пишутся для постороннего читателя.** Никаких «решение сессии», «пользователь попросил», «см. раздел N» — только причина по существу. Слово «пользователь» означает клиента продукта, а не заказчика разработки.
- В репозиторий не попадают `.claude/` (кроме этого скилла), скриншоты рабочих проверок, локальные документы.

## Выкладка на сервер

Прод разворачивается **нативно, не в Docker**: одна машина, SQLite файлом, файлы на диске. Compose в репозитории — только для локального запуска.

Порядок обновления: остановить службу → сделать копию базы → `git pull` → `npm run build` → `npm run db:migrate` → запустить службу. Всё, кроме управления службой, выполнять от того пользователя, которому принадлежит каталог приложения: если развернуть от `root`, а служить от другого пользователя, первый же `git pull` упадёт на правах внутри `.git`.

Приложение слушает локальный адрес, наружу его выставляет веб-сервер с TLS. Переменная `HOST` по умолчанию `0.0.0.0` ради Docker — на машине, где рядом стоит веб-сервер, в `.env` обязателен `HOST=127.0.0.1`, иначе порт API смотрит в интернет мимо TLS.

Миграции и админские команды запускаются через `tsx` из `devDependencies` — ставить зависимости с `--omit=dev` на проде нельзя.
